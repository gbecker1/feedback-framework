Feedback Framework

Set up your own live feedback room

A step-by-step guide to stand up an anonymous, phone-based audience-feedback tool: attendees scan a QR per item and rate it; a projector shows a live Value × Effort heat map and an auto-ranked priority list. About 20 minutes, all free-tier.

What this is

Three small screens, no server code of your own:

📱 Phones
feedback.html?uc=…
→
☁️ Firebase
Realtime Database
→
🖥️ Projector
results.html

Phones write anonymous ratings into Firebase; the projector reads them live and draws the heat map + ranking. It's plain static files (HTML/JS/CSS) with no build step. If Firebase isn't configured yet, everything still runs in a local-preview mode that saves to the browser only — handy for trying it before you wire up the database.

Prerequisites

  • A Google account (for Firebase — free).
  • A GitHub account (for free hosting via GitHub Pages). Optional if you host elsewhere.
  • Python 3 installed, to preview locally (python3 --version). Any static server works.
  • A modern browser. That's it — everything here is free-tier.

Get the files

Copy the whole feedback-framework folder to your machine. Quick tour:

FileWhat it is
feedback.htmlThe mobile form (one item via ?uc=…).
results.htmlThe projector view: heat map + ranking + export.
index.htmlRedirects to results.html.
js/config.jsYou edit this — items, questions, branding, colours.
js/firebase-config.jsYou edit this — your Firebase keys.
everything elseEngine — leave it alone.
The one rule: you only ever edit js/config.js and js/firebase-config.js.

Create a Firebase project

  1. Go to console.firebase.google.com and sign in.
  2. Click Add project, give it a name (e.g. my-feedback), Continue.
  3. You can turn off Google Analytics — it's not needed. Click Create project.

Enable Realtime Database

  1. In the left menu: Build → Realtime Database.
  2. Click Create Database.
  3. Pick a region closest to your audience (e.g. Belgium / europe-west1). This gets baked into your database URL — just remember which one you chose.
  4. When asked, start in locked mode (we set the rules in the next step).

Set the database rules

Open the Rules tab of the Realtime Database and paste this, then click Publish:

{
  "rules": {
    "feedback": { ".read": true, ".write": true },
    "$other":   { ".read": false, ".write": false }
  }
}
Security note: this allows anyone with the link to read and write the feedback node. That's fine for a short, anonymous, throwaway feedback round — but don't store anything sensitive, and tighten or disable the rules after your event. For a time-boxed safeguard you can instead use ".write": "now < 1735689600000" (a Unix-ms expiry); if writes suddenly stop, an expired rule like this is the usual cause.

The node name feedback must match storage.dbNode in your config (it already does by default).

Paste your Firebase config

  1. In Firebase: Project settings (gear icon) → Your apps → Web (</>) → register an app (any nickname, no hosting needed).
  2. Firebase shows a firebaseConfig = { … } snippet. Copy its values.
  3. Open js/firebase-config.js and paste each value over the matching REPLACE_ME:
export const firebaseConfig = {
  apiKey:            "AIza…",
  authDomain:        "my-feedback.firebaseapp.com",
  databaseURL:       "https://my-feedback-default-rtdb.europe-west1.firebasedatabase.app",
  projectId:         "my-feedback",
  storageBucket:     "my-feedback.appspot.com",
  messagingSenderId: "123456789",
  appId:             "1:123…:web:abc…",
};
Good to know: while any value still says REPLACE_ME, the app runs in local-preview mode (saves only in your browser). That's expected until you paste the real values — a yellow banner reminds you.

Edit config.js

This is where you make it yours. Open js/config.js and edit these blocks:

Items — the things people rate

items: {
  idPrefix: "UC",            // the short badge strips this (UC01 → "01")
  list: [
    { id:"UC01", category:"cat1", tag:"Sales", title:"Automatic quote from an email",
      lead:"An inbound request becomes a priced quote on its own." },
    { id:"UC02", category:"cat2", tag:"Service", title:"Where is my order?",
      lead:"The agent answers status / ETA / delivery questions." },
    // add as many as you like — each gets its own QR link
  ],
},

Each item's category points at a key in theme.categories (that's what colours its bubble on the heat map).

Questions

Two 1–5 tap scales plus three chip multi-selects. Edit labels, hints and options freely. The "add your own" box is automatic.

Keep these keys: the two scales must stay keyed value and effort — the heat map plots value (up) against effort (right).

Branding & colours

  • brand.orgName / titleSuffix — the wordmark and tab title.
  • brand.logoSvg (inline SVG) or brand.logoImg ("img/logo.png") — optional logos.
  • theme.palette — your accent colours; theme.gradient — the headline gradient.
  • theme.categories — one colour per item group.

Run it locally

You must serve it over http — opening the files directly (file://) breaks the JavaScript modules. From inside the folder:

cd feedback-framework
python3 -m http.server 8000

Then open:

  • http://localhost:8000/feedback.html?uc=UC01 — a form
  • http://localhost:8000/results.html — the projector view

Submit a few test votes, open the results in a second tab, and watch them appear. (Once Firebase is configured, two different devices sync live; before that it's per-browser only.)

Deploy to GitHub Pages

  1. Create a new repo on GitHub (e.g. feedback-framework).
  2. Push the folder's contents:
cd feedback-framework
git init
git add .
git commit -m "Feedback framework"
git branch -M main
git remote add origin https://github.com/YOURNAME/feedback-framework.git
git push -u origin main
  1. In the repo: Settings → Pages → Deploy from a branch → branch main, folder / (root) → Save.
  2. Wait ~1 minute, then your site is at https://YOURNAME.github.io/feedback-framework/.
  3. Put that URL into deploy.baseUrl in config.js, commit and push again.

Make the QR codes

Each item has its own link in this shape:

https://YOURNAME.github.io/feedback-framework/feedback.html?uc=UC01
https://YOURNAME.github.io/feedback-framework/feedback.html?uc=UC02
…one per item id…

Turn each link into a QR code with any free generator (e.g. qr-code-generator.com, or your browser's built-in "Create QR code for this page"). Print one per item and place it at that station. Tip: also print the short URL under each code for anyone who can't scan.

Test first: open one QR link on your own phone and confirm the right item's form loads before you print the batch.

Run the session

  • Open results.html full-screen on the projector.
  • As you present each item, attendees scan its QR and rate it on their phones.
  • The heat map and ranking update live. One vote per phone per item — re-scanning lets someone change their answer.
  • At the end, use Download CSV (all data) and Results image (a shareable PNG).

Troubleshooting

SymptomLikely cause → fix
Yellow "local preview" banner won't go awayA REPLACE_ME is still in firebase-config.js, or a typo in a value.
Votes not landing / "permission denied"Rules not published; node name mismatch (rules say feedback but storage.dbNode differs); or wrong databaseURL region.
"Permission denied" that used to workA time-limited rule expired — re-open the rules (Step 6).
Blank page / module or CORS errorsYou opened it as file://. Use python3 -m http.server or the Pages URL.
Projector empty but phones say "sent"The results tab was opened before Firebase was configured — reload it.
QR scans to a 404deploy.baseUrl is wrong or missing its trailing /, or the site isn't deployed yet.
Fonts/logo missingOffline or the CDN is blocked — the app still works, it just falls back to system fonts.
